Help

How to use AI Workshops Share

First time

  1. Run node server.js and open the address it prints (http://localhost:3000 by default). Keep that window open while you work: scans and sharing run inside it.
  2. Click Settings, fill in the fields below, and click Save. They are written to config.json in the app folder (a backup is kept as config.json.bak). You can also edit that file directly and restart.
  3. The project list loads. Use Reload next to the project count to refresh it.

Settings: Smartsheet

  • API key: your Smartsheet API token (in Smartsheet: Profile, Personal Settings, API Access, Generate new access token). The app uses it for everything, so sharing and sheet changes appear as you and follow your permissions. It is never shown again after saving, only the last four characters. Leave it blank later to keep the saved one.
  • Base URL: the Smartsheet API address. Leave it as https://api.smartsheet.com/2.0 unless your account is on another region, such as the EU or Gov address.

Settings: Portfolio

A portfolio is one project list, such as AI Workshops. The first portfolio in the list is the one the app uses. Add copies the current one and Remove deletes one.

  • Name: a label for the portfolio. It appears in the log and messages.
  • Project list sheet ID: the numeric ID of the Smartsheet sheet that lists your projects. In Smartsheet, open the sheet, then File, Properties, and copy the Sheet ID. This sheet is what the app reads and updates.
  • Workspace access: the permission each participant gets on their whole project workspace, including every sheet in it. Admin is recommended so participants can add columns and manage their own tracker. The options are Viewer, Commenter, Editor, Editor (can share) and Admin. Smartsheet only allows Admin for licensed users. If a project is already shared at a lower level, running Activate and share again upgrades it.
  • Tracker sheet name: the name of the sheet inside each workspace that the participant works in, such as Community Project Tracker. Analytics reads this sheet, and it is the sheet given the extra access below.
  • Tracker sheet access: an optional extra permission on the tracker sheet only. Leave it as NONE when the workspace access already gives enough, which is the case with Admin on the workspace. Pick a level only if you need the tracker to be higher than the rest of the workspace.
  • Active value: the text in the Workspace Status column that means a project is active, normally Active. Activate and share sets this value, and the workspace is created from it.
  • Poll every (seconds): how often the page checks whether a workspace is ready while you wait. 5 is fine.
  • Workspace timeout (seconds): how long to wait for a workspace to appear before giving up on a project and marking it as an error. 600 is the default, because the check runs only about once a minute when the page is closed.
  • Send Smartsheet invite email: when ticked, Smartsheet emails the participant their invitation when the workspace is shared. Untick it to share silently.

Settings: Invite email text

  • Send me a copy: Smartsheet also emails you a copy of each invitation.
  • Subject and Message: your own wording for the invitation Smartsheet sends when a workspace is shared. Blank uses Smartsheet's default. You can use {name} (project name), {workspace} and {url} (the workspace link). These only apply when the invite email is on.
  • Attachments: Smartsheet cannot attach files to this email. To give participants a file, add it to the workspace or tracker sheet as an attachment, or put a link in the message.

Settings: Analytics quick check

  • Cells checked first: one per line as Column name, row number, for example WBS ID, 22. Analytics reads the history of just these cells first. If the participant edited none, the scan stops early as a partial scan with no changes. Row number is the number shown in Smartsheet. Empty the box to always do the full scan.

Settings: Column names in the project list

These must match the column titles in your project list sheet exactly, so the app knows where to read and write.

  • Project name: the project name column. The name must be the participant's email address, which is who the workspace is shared with.
  • Workspace status: the column the app sets to Active.
  • Date: the workshop date, used by the date filters.
  • Location: used by the location filter.
  • Type / client: used by the client filter.
  • Shared: a checkbox column the app ticks once the project is shared.
  • Attended: a checkbox column showing whether the participant attended. Analytics hides projects where it is not ticked, since there is nothing to scan. If the column doesn't exist, nobody is hidden.

Activate and share

  1. Use the filters on the left (date, location, client, active, shared) to narrow the list. Hide filters / Show filters at the top collapses the panel for more room, and the app remembers your choice.
  2. Tick the projects you want. Only projects with an email address as the name can be ticked.
  3. Click Activate and share. Each project is set to Active, then once its workspace exists it is shared with the participant, the tracker sheet access is set, and Shared is ticked.
  4. You can close the page. The server keeps checking every few seconds and the status is there when you return.

Analytics: scanning

  1. Click Analytics. Earlier results appear straight away.
  2. Attended only is ticked by default and hides projects not ticked as attended. Untick it to include everyone. The other filters apply too.
  3. Click Scan new projects to scan projects that have no result yet, including stopped or failed ones.
  4. Quick check first: each scan reads 5 key cells (Start Date row 8, End Date row 5, Status row 8, WBS ID rows 22 and 36). If the participant has not edited any, it finishes in seconds as "Partial scan of these rows returned no changes". If they have, the full scan continues, reading every cell. This takes a few minutes per project.
  5. Only edits by the participant (the email in the project name) count. The bar length is the number of changes, and the colour shows how recent the last one was.

Analytics: stop and re-scan

  • Stop scan appears while a scan runs. Results found so far are kept, and stopped projects show "Stopped at N%".
  • To scan again, tick the projects (or Select all shown), then choose:
    • Quick re-scan selected: checks the 5 key cells first. If the participant edited none, it stops in seconds with "Partial scan of these rows returned no changes". If they edited any, it carries on to the full scan. Use this for routine re-checks.
    • Full re-scan selected: skips the quick check and reads every cell. It takes a few minutes per project and gives a complete count of the participant's changes. Use it when you want the whole picture.
  • You can close the page during a scan. It carries on as long as the server window stays open.

Settings and the log

  • Settings also hold the tracker sheet name, access levels, and the Analytics quick check cells (one per line as Column name, row number).
  • Log shows everything the app has done for you, newest first. The last 1,000 entries are kept.

Good to know

  • All sharing is done with the API token in config.json, so it appears as that person in Smartsheet and uses their permissions. Scans, jobs and the log are kept in the data folder.
  • Smartsheet only allows Admin on a sheet for licensed users, so unlicensed participants show an error.
  • A change is one cell edit by the participant. Edits made under a different email address than the project name are not counted.
